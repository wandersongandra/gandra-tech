# Política de Segurança

A segurança deste projeto deve ser tratada de forma responsável e privada.

## Relato de vulnerabilidades

Não publique credenciais, tokens, dados pessoais, detalhes de exploração ou vulnerabilidades ainda não corrigidas em issues públicas.

Ao identificar uma possível falha de segurança, utilize um canal privado de contato com o mantenedor indicado no perfil do GitHub e informe, sempre que possível:

- componente ou versão afetada;
- descrição objetiva do problema;
- passos mínimos para reprodução;
- impacto potencial;
- evidências sem dados sensíveis;
- sugestão de correção, quando houver.

## Segredos e credenciais

Credenciais reais, arquivos `.env`, tokens, chaves privadas, cookies, dumps de banco e dados de produção não devem ser versionados.

Exemplos de ambiente devem utilizar apenas placeholders claramente fictícios.

## Dependências

Dependências com vulnerabilidades de severidade alta ou crítica devem ser avaliadas antes de mudanças serem promovidas para produção.

## Divulgação

Detalhes técnicos de uma vulnerabilidade devem permanecer privados até que exista correção ou mitigação adequada.
